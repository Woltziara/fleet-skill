# Fleet · 星河舰队

简体中文 | [English](README.en.md)

一个用于 Codex 的有界多 Agent 协作 Skill：**只有委派存在净收益时才增加调度层，按任务选择模型、推理强度和上下文，并由主 Agent 汇合、验收。**

Fleet 是指导 Agent 如何工作的指令包，不是新的运行框架。它不安装服务、不接入外部付费模型、不创建后台监控，也不提供额外权限。

## 它解决什么问题

- **不为并行而拆分。** 高度耦合的整体判断留给主 Agent；独立、可验证的单元才委派。
- **不默认继承最贵配置。** 模型、推理强度和输入范围分别选择，考虑实现、交接、验收及返工总成本。
- **共享资源有明确写入负责人。** 文件、浏览器、数据库等都需要划分所有权；接管前先确认原执行者停止写入。
- **回收结果，而不只收一句完成。** 子 Agent 提供实际产物与证据，主 Agent 做相称的整合验证。
- **长程不等于多人。** 跨阶段工作需要持续调度，但不要求开满并发或新建治理流程。
- **昂贵主循环保持稀疏。** 主 Agent 保留任务合同、冲突、整合与最终采纳；可闭环的批量阅读、常规施工、测试和返修交给合适执行者。
- **困难单元按证据上派。** 只有关键分歧无法收敛，或同档已暴露能力不足时，才把完整判断单元交给更强模型。

## 安装

将本仓库的 `skills/fleet` 文件夹完整复制到你的 Codex Skill 目录。例如：

- 个人使用：`~/.agents/skills/fleet`
- 仅当前项目：`<项目>/.agents/skills/fleet`

如果目标已有同名 Skill，先比较并备份，不要直接覆盖自己的修改。必须同时复制 `references/core.md`，它是入口引用的共同方法。

也可以对 Codex 说：

> 从 https://github.com/Woltziara/fleet-skill 安装 skills/fleet。

安装和发现机制以你的 [Codex 当前说明](https://learn.chatgpt.com/docs/build-skills)为准。

## 使用

明确调用：

> 使用 $fleet 完成这项任务。先判断哪些工作值得并行，合理选择子 Agent 的模型和推理强度，保留整体责任，最后汇合并验证。

也可以自然地要求“用 Fleet”“星河舰队”或“编队完成”。没有实际有净收益的委派、并行或共享写权协调时，长程任务仍由主 Agent 直接推进，不仅因为任务时间长就进入 Fleet。

**没有子 Agent 能力或宿主不允许委派时，继续由主 Agent 完成可做的工作，不伪造委派。** 具体工具名称、并发上限、模型和参数以运行环境为准。

## 任务结束后的用量统计

Fleet 保留实际模型、推理强度、工作单元、采纳与返工事实。有宿主现成的可归属 usage 时报告实际值；没有时明确写“未提供”。只有用户要求评估，或宿主已经提供自动完整计量时，才生成覆盖全部运行的统计表。

精确 Token 取决于宿主是否提供可归属的用量回执。缺失时明确标注“未提供”，报告已知小计和统计覆盖率，不将它冒充任务完整总量，也不把额度百分比、预算或模型估计当作实际消耗。当前最终回复尚未产生的用量不计入此前快照。

## 内容

```text
skills/fleet/
├── SKILL.md
├── agents/openai.yaml
└── references/core.md
```

- `SKILL.md`：Codex 调度适配、实际选型与调用约束。
- `references/core.md`：委派资格、共享资源、成本、收回与汇合方法。
- `agents/openai.yaml`：显示名称和默认调用提示。

## 公开版边界

这是个人实践版本的可移植发布：将共同方法放入仓库、去掉私人规则路径、可选外援依赖和本机观测回执，并将特定模型名称转换为能力档位。没有包含私人会话、项目数据、凭据或本机配置。

它不承诺固定节省比例，也不保证任意模型、任务或宿主下的结果。实际质量、成本与收益应根据真实任务的交付和返工核验。本项目不是 OpenAI 官方发布或背书。
