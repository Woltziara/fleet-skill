# Fleet · 有界委派与汇合

## 稳定职责与边界

帮助当前负责人利用并行执行、专门上下文或独立复核完成用户任务。是否分工、怎样拆分和何时收回，由现场依赖与总成本决定；意图、权限和最终交付仍属于原任务。

这是委派方法，不是所有复杂任务的开工制度。用户指令、宿主权限和项目规则继续适用；只有任务明确要求额外的长任务治理或项目合同依赖它时，才读取对应项目的相关约束。不得因为调用 Fleet 就加载整套旧制度、创建合同、画流程图或新增审批。模型、接口与宿主权限由对应 adapter 消费当前能力，不在共同正文固定。

## 何时委派

长程任务先做一次直接执行／委派判断。只有实际存在有净收益的委派、并行、共享写权协调，或用户明确要求 Fleet 时，才正式进入 Fleet；没有实际委派就直接执行，不触发 Fleet 运行记录或统计。为同一终局跨多个实质阶段、中间反馈会改变后续动作，需要持续保住目标、已定决定与工作状态，才属于长程任务；单纯等待长命令、回答篇幅长或文件多不自动算长程。

用户明确要 Fleet、星河舰队、编队、并行或 Agent 队伍时也进入。只说“节俭”“省 Token”不单独触发编队，但成本是每次实际派工都必须考虑的因素；不以用户这轮未提成本为由忽略。

在当前授权和宿主允许委派的范围内，只要现场已知的依赖、上下文与验证方式支持“预计能节省时间、保住主上下文或获得有价值的独立信息”，即可作一次有界委派。普通原生同能力委派不先做收益实验；预期仍是预期，不能把它写成已证实节省。

有接口依赖不代表整项工作不能并行：先明确双方共同依赖的接口或输入版本，再分开实现、取证和检查；不能同时改动仍未定的共同语义。高度耦合的整体判断保留在负责人处；确定性的重复操作可能由程序直接完成更合适。用户明确要求并行时尽可能兑现有价值的分工；确实不可安全拆开则说明原因，继续完成任务，不为凑人数造角色。

## 分工与共享资源

委派前只恢复足以划分工作与验收的现场，不先穷举所有文件、测试和部署面。执行委派应替代负责人原本要做的一块工作，而非在同一工作上再叠一层。优先交出可自行完成、自验和局部修复的完整工作单元；小活若移交与验收比直接做更重，就直接完成。派出后，负责人继续互补工作；没有互补工作就等待，不重复协作者的调查。独立审查可以有必要的重复，但属于质量投入，不能冒充工作转移或已降本。

一条任务消息应足以让协作者知道：要交什么、必要输入与有效版本、允许的动作／文件、怎样证明结果，以及遇到什么情况需要返回。已经给出的信息可直接引用；无关字段省略。只有真实接收端要求时才使用固定 schema、枚举或严格封套；自然语言和文件路径也可构成有效交接。

- **共享资源先分写权。** 不只看文件：同一个浏览器标签、应用窗口、数据库、索引、构建输出或发布目标也会冲突。同一时刻一个写 owner；能用独立临时输出或 worktree 才隔离，隔离分支仍需检查逻辑冲突。
- **身份与版本要能对上。** 输入只在需要的稳定边界冻结，不冻结协作者的技术路线。接口或输入变化只失效受影响结果；及时通知相关协作者，不让旧结果混入新验收。
- **上下文按任务给。** 执行者取得必要背景；独立冷读不给生产者结论或期望答案。隔离只是一种证据条件，不自动等于模型异质、独立重算或正确。
- **授权随任务边界传递。** 协作者可在分配范围内自行查明技术细节、修复和验证，不为普通歧义停止整个任务。需要新方向、权限或副作用时，仅暂停相关部分并交负责人判断；负责人也先复用原有用户授权。

纯文本任务若确实只需给定输入，可限定不调用工具；需要现场事实的执行者则应获得足够的只读或局部施工权限。不要用“窄任务”当成剥夺必要上下文的理由。

## 调度、收回与成本

并发数取决于当前宿主容量、瓶颈与可独立交付单元，不要求固定梯队或凑满槽位。当前主模型对每个派出单元选能力：看尚需解决的判断与歧义、整体背景依赖、错误后果及是否容易发现和修复。项目整体很难不代表每个子任务都难；先把输入、接口和验收说清，能让较低成本能力可靠完成的部分就交给它。

在质量和权限底线内比较执行、上下文、验收及预期返工的总成本；确定性操作优先程序，模型任务从合理低成本档起步，难点可直接选强档，不强制逐级试错。模型、推理强度和输入范围分别选择，不能由主模型的当前配置自动决定；具体可用模型和起始映射只在 adapter 维护。

高推理成本主循环保持稀疏：保留任务合同、不可约冲突、跨单元整合、异常裁决和最终采纳；批量阅读、常规施工、测试、局部诊断与范围内返修，优先交给能够闭环的低综合成本执行者或程序。主循环能做不代表应由主循环做。高度耦合的工作不为稀疏而强拆。

难度以实际输入和剩余判断为准，不能仅因任务带有“会议、语义、专业、审计”等标签就选高档。材料不足时先恢复必要事实；尚未观察到的歧义不当作已经存在的困难。选强档的理由应指出具体待解判断或难以发现的失败，而不是泛称“更稳健”。

普通有界任务用选型理由直接开工，不先造评分器或跑全模型实验。缺少适用证据的批量高后果扩散才需要可回收小样；已有同类有效证据复用。失败先区分缺输入、工具错误与能力不足，再补资料、调整任务或升级，不能把所有失败都归因于模型不够贵。边界内的局部缺陷优先让原执行者依据失败证据修复，负责人不默认接管重写；若反复需要负责人逐步指导、重复调查或大面积重做，立即重看任务边界、输入和选型，合并、改派或收回。续派的工作变化时重看选型；改派先履行停写与接管边界。

保留足够复盘的精简记录：子任务与选型理由、实际模型／推理／上下文方式、产物与验收、必要的返工或升级。优先复用派工消息和任务已有状态；缺实际时长、用量或计费记录就保持未知。积累几次真实 Fleet 使用后按总成本与结果质量复盘，不把本次合成检查计作真实收益，不设每日任务。

嵌套委派只在负责人允许、宿主容量足够且结果能清楚归回时使用；不能递归扩张成无人负责的队伍。外部 API、物理机器或持久工位按当前宿主的独立授权与运行边界处理，Fleet 不增加外发、费用或写权。

等待只卡住真正依赖该结果的部分。优先等状态变化，避免无信息的高频轮询。出现超时、连续无交付、复核反而更贵或关键前提变化时，缩小、改派或收回该单元；可用的其他结果继续集成。

**收回写任务前先停原写 owner 并确认停写／隔离。** 未确认之前，不把同一目标交给新 owner，也不让负责人抢写；可先在隔离位置准备修法。保留已有结果和用户改动，不能用全局回滚清理协作现场。

## 汇合与完成

协作者完成自己的局部单元，包括范围内的必要修复与验证；返回实际产物／diff、关键证据、未决限制及原始材料位置，不默认倾倒全部探索日志。负责人围绕关键主张、变更和交叉接口做相称核验，需要时再取原文或日志；不把从头重复全过程当作默认验收。专业判断可由来源、反例或独立观察复核，不要求一切都变成确定性单元测试；既有权威要求的独立复核仍保留。

协作者自报完成只表示待采纳；“没找到问题”不能证明整体正确。已采纳结果不要求负责人无条件重做全部检查；只有新改动、新失败、集成风险或证据不足时扩大验证。达到用户本次结果后直接交付，不停在派工计划或候选就绪，也不为长期收益尚未发生而拖住当次完成。

最终答复先交用户结果、实际验证与重要限制；发生实际委派时，再简述协作者完成并被采用的工作及重复劳动、接管或返工。工作转移是行为证据，不等于 Token 或费用已下降。其他中间材料仅在恢复、回放或交接确有需要时保存，不因“用了舰队”新建长期账本或后台任务。

## 大任务结束后的模型与 Token 统计

只有实际进入 Fleet 且用户明确要求评估，或宿主已有自动完整计量时，才制作完整覆盖统计表。其他情况下，有宿主现成 usage 就报告实际 usage；没有时一句说明“usage 未提供”，同时保留实际模型／强度、工作单元、采纳与返工事实。不制作全是缺失项的完整表。没有实际委派无需 Fleet 统计。

- 从派工开始在现有任务记录中保留子任务、Agent/运行标识、父子关系、实际模型与推理强度、续派/返工/升级和结果。以工具确认的配置为依据；只有请求配置时标明“请求模型，实际未核实”。复用 Agent 做不同子任务时记录边界，不把整段会话用量任意分摊。
- 优先使用宿主或 provider 的实际 usage 回执；只读取本任务相关的用量元数据，不为统计扫描无关会话、读取隐藏思考或导出原始日志。记录计量来源、时间范围、单位与是否包含子 Agent。拿不到的字段写“未提供”，不能写 0、让模型自估、按文本长度估算或用预算/额度百分比替代。
- 输入、输出、总 Token 按来源语义统计；缓存输入、推理输出若是其中的子集就只作明细，不再次相加。累计快照取末值或同范围起止差，不能逐次累加；请求按唯一标识去重。计数重置、跨会话、不同计量口径或归属不明时分别列出，不强凑总数。
- 覆盖全部子任务及嵌套委派，包括失败、取消、重试和未采纳结果；多轮续派按实际可归属粒度列示。只有 Agent 总用量而无子任务明细时，将相关子任务列在同一行并注明无法拆分。主 Agent 的协调、验收用量单列；父级总量若已含子级，不能再加子级。
- 只有用户明确要求评估或已有自动完整计量时，才要求覆盖全部运行并给明细表及汇总；其他情况下不强制完整覆盖表。没有委派无需写 Fleet 统计。
- 只有范围一致、去重且全部所需用量齐全时才称“任务总 Token”；否则称“已知用量小计”，同时列缺失运行、无法拆分项及未计入的主 Agent 开销。说明统计截止时间；当前最终回复尚未产生的用量不假装已计入。Token 不是账单，没有计费依据不推算金额或已节省比例。

需要统计时复用现有用量来源，不新建后台采集器、固定轮询或跨任务账本。字段缺失不阻断已经完成的业务交付；无实际 usage 时按上文一句说明未提供。
